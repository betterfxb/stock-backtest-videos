## 一、整体流程（五阶段）

```
选题立项 → 数据获取 → 回测分析 → 内容制作 → 发布运营
```

| 阶段 | 核心动作 | 交付物 | 卡点 |
|---|---|---|---|
| **一、选题立项** | 确定标的、填写选题卡、合规预检 | 选题卡 | 四参数齐全；合规预检通过 |
| **二、数据获取** | 拉取数据、清洗校验、异常确认 | `raw_prices.csv` + 校验报告 | 异常跳变 > 30% 须人工确认 |
| **三、回测分析** | 净值化、指标计算、节点筛选、宏观归因 | `nav.csv` + `metrics.json` + `nodes.csv` + `events.csv` | 节点数 8-12；每节点有真实事件 |
| **四、内容制作** | 钩子设计、文案撰写、画面渲染、视频合成 | `final.mp4` + 封面图 | 3 秒钩子评分 ≥ 8；合规条全程可见 |

### 2.3 回测分析

#### 2.3.1 指标体系

| 指标 | 公式 | 是否上画面 |
|---|---|---|
| 总收益率 | `(期末 - 初始) / 初始` | ✅ 主数字 |
| 含息总收益率 | `(期末市值 + 累计分红 - 初始) / 初始` | ✅ A 股必备 |
| 含息年化收益率 | `(含息总资产/初始)^(1/年数) - 1` | ✅ 字幕第二行 |
| 年化收益率 | `(期末/初始)^(1/年数) - 1` | ⚠️ 不含息须标注 |
| 最大回撤 MDD | `min((P_t - P_s)/P_s)` | ✅ 结尾段必须出现 |
| 回撤区间时长 | 从前高到前低的天数 | ❌ 内部 |
| 最大回撤修复天数 | 从前低回到前高的天数 | ❌ 内部 |
| 波动率（年化） | `std(日收益率) × √252` | ❌ 内部 |
| 最大浮亏 | `min(P_t/初始 - 1)` | ❌ 内部 |
| 持有正收益占比 | 上涨交易日数 / 总交易日数 | ❌ 内部 |
| 累计分红 | 逐次除息日派息 × 持股数 | ❌ 内部 |

**特殊处理**：
- 非分红标的（黄金、原油、ETF）：只展示不含息口径
- 最大浮亏 ≈ 0%（起点即最低点）：改为展示「买入后最大回撤」
- 分红口径：统一为「现金到账」，画面标注「分红未再投资」

#### 2.3.2 节点筛选规则

| 规则 | 标准 | 实现 |
|---|---|---|
| 起点 | 回测起始日；若起始日非区间极值，补充最近极值日 | 代码实现 |
| 阶段极值 | 滚动 12 个月窗口内极值 | 代码实现 |
| 大拐点 | 相对 12 个月前涨跌幅 > 12% | 代码实现 |
| 宏观事件日 | 央行议息、CPI 发布、财报披露、重大政策日 | `westock news` 筛选 |
| 终点 | 数据截止日 | 强制保留 |

**合并收敛**：
- 相邻节点间隔 ≤ 2 个月视为同一段，保留该段极值（最高或最低）
- 合并后仍多于 12 个，按「距前 12 个月波动幅度」降序取前 10 个
- 节点数不在 8-12 区间直接判定「需重筛」

### 2.4 内容制作

#### 2.4.1 3 秒钩子设计规范（新增）

**5 种钩子类型**：

| 类型 | 形式 | 适用场景 | 示例 |
|---|---|---|---|
| 悬念式 | 抛出反常识判断 | 观点类、分析类 | 「假如你不小心买在了最高点」 |
| 视觉冲击 | 快切 + 大字 + 动态箭头 | 数据类、对比类 | 「100 万变 254 万，中间经历了什么？」 |
| 情绪共鸣 | 点名群体身份 | 泛受众 | 「所有 30+ 投资者注意」 |
| 承诺式 | 明确价值承诺 | 教程类、工具类 | 「看完这条视频，你就知道该不该拿住」 |
| 争议式 | 与主流观点相反 | 观点类 | 「长期持有本身就是一种运气」 |

**5 维度评分公式**（满分 10 分）：

| 维度 | 评分标准 | 满分 |
|---|---|---|
| 明确性 | 3 秒内能 get 这条视频是给谁看的 | 2 |
| 新奇性 | 打破常规开场套路 | 2 |
| 承诺性 | 观众能预期看完获得什么 | 2 |
| 情绪强度 | 第 1 秒画面或文字的情绪冲击力 | 2 |
| 平台契合度 | 符合平台语感 | 2 |

**合格标准**：≥ 8 分；淘汰标准：< 6 分

#### 2.4.2 叙事结构

**A 型（磨底 → 主升）**：适合「买在低点、长期持有后起飞」的标的

```
① 钩子        0–3s     结果前置 + 悬念
② 起点        3–8s     买入当下，收益率极低
③ 磨底        8–32s    长时间停滞/回撤
④ 主升        32–58s   收益率陡峭上行
⑤ 高点        58–78s   收益峰值
⑥ 回落+收尾   78–86s   冲顶回撤，落到期末真实值
```

**B 型（主升 → 磨底）**：适合「买在高点、长期套牢」的标的

```
① 钩子        0–3s     结果前置 + 悬念
② 起点        3–8s     买入当下
③ 主升        8–20s    早期上涨
④ 冲顶        20–25s   收益峰值
⑤ 长期磨底    25–75s   长时间停滞/回撤
⑥ 收尾        75–86s   弱反弹或继续下跌
```

**亏损型**：适合回测结果为负的标的

```
① 钩子        0–3s     结果前置（亏损数字）
② 起点        3–8s     买入当下
③ 主升        8–20s    早期上涨（如有）
④ 冲顶        20–25s   收益峰值
⑤ 长期下跌    25–75s   持续下跌/横盘
⑥ 收尾        75–86s   期末亏损数字
```

#### 2.4.3 节奏控制规范（新增）

| 维度 | 标准 |
|---|---|
| 信息密度 | 每 15-20 秒一个信息点 |
| 节点停留 | 每个节点 3-5 秒；**最短停留 90 帧（3 秒），分段配速见 2.4.10** |
| 转场方式 | 淡入淡出（0.5 秒）或滑动（0.3 秒） |
| 节奏变化 | 至少 3 次（快→慢→快 或 慢→快→慢）；跨度大的段自动多占帧（见 2.4.10） |
| 结尾留存 | 最后 5 秒必须有「总结 + 引导互动」 |

#### 2.4.4 事件卡文案规范

**句式**：`日期 · 类型` / `一句话数字结论` / `宏观原因 + 具体日期 + 资产数值`

##### 2.4.6.1 动态纵轴（v4.1 新增，强制）

**固定纵轴是叙事失败，不是"更稳重"。** 早期版本把 `YMAX` 锁死为全区间峰值，
理由是"实时重标定会导致跳轴、显得卡顿"。实测这个取舍是错的：

| | 固定轴 YMAX=8000 | 动态轴 |
|---|---|---|
| 长熊段 idx7~38（净值 78~474 万）平均月波动 | **0.70px** | **14.06px**（20 倍） |
| 全区间月波动 < 2px（即"看不出起伏"）的月份 | 50 / 80 | 9 / 80 |

0.7px 的起伏在屏幕上等于一条直线。观众看到的是"六年半涨 45 倍"的文案配一条
平直的线，**没有任何视觉证据**支撑这个结论。所以纵轴必须动态。

**但不能直接用瞬时值**，否则每个月的小波动都会让刻度数字乱跳，比"没起伏"更糟。
三条硬约束：

| 约束 | 做法 | 目的 |
|---|---|---|
| 跟随**窗口**最大值，不是当前值 | 取相机 13 个月窗口内 `max(净值)`，再乘 1.18 留白 | 已画出的历史峰值不会被下一帧顶出画面 |
| 上升即时，下降缓慢 | `release = max(target, release × 0.9965)` | 突破立刻给空间；缩回来约 1 秒降 10%，不抖动 |
| 顶值恒为 `step × 4` | `step ∈ {25,50,100,200,250,500,1000,2000,2500}` | 5 条刻度全是整数，不出现 62.5 这种数 |

上限 `top ≤ 10000`（step=2500）：再高会让「10,000」这类 6 字符标签铺到 `x<80`，
吃掉左侧安全带。

**下降必须衰减连续量，不能衰减量化值（v4.2 修正）**

衰减状态量 `release` 要保持**连续**，`top` 只是它的量化投影：

```
release = target >= release ? target : max(target, release * DECAY)
top     = fitStep(release) * 4
```

若写成 `prev = top`（存量化后的档位）会收敛到一个**不动点**：`prev = 800` 时
`prev × 0.9965 = 797.2`，`fitStep` 又把它吸回 `800`，下一帧 `prev` 仍是 `800` ——
纵轴**永远降不下来**。

这个 bug 在第 004 期就已存在，但当时被误判为"数据本身单调"：第 004 期记录
"7 次换档且从不下降"，实际是 `target` 在 400/800 间反复变化、却被衰减不动点
压死在 800。后果是长期回撤段被锁在高档位，曲线占幅只有 25%（第 005 期实测
75px / 300px），42 个月的横盘在屏幕上接近一条直线 —— **恰好是动态轴本该消除
的那个问题**。修正后同一段占幅升到 50%~80%（150~242px），起伏才真正可见。

**回归校验**：每次改动 `axis.ts` 后，必须打印 `top` 的**连续段时长**，而不只是
"换了几档"。若存在超过 20 秒的单段，说明又被压住了：

```bash
node -e "import('./out/axis.mjs').then(m=>{const t=m.AXIS_TOP;let s=0,v=t[0],segs=[];for(let f=1;f<t.length;f++){if(t[f]!==v){segs.push([s,f-1,v]);s=f;v=t[f]}}segs.push([s,t.length-1,v]);segs.forEach(([a,b,x])=>console.log('  f'+a+'..f'+b+'  top='+x+'  '+((b-a+1)/30).toFixed(1)+'s'))})"
```

第 005 期（北方华创 sz002371）实测连续段：

```
f0..f328      top=200    11.0s
f329..f702    top=400    12.5s
f703..f1012   top=800    10.3s
f1013..f1922  top=400    30.3s   ← 42 个月回撤段降档，占幅 50~80%
f1923..f2497  top=800    19.2s
f2498..f2526  top=1000    1.0s
f2527..f2759  top=2000    7.8s
```

**已知代价（接受）**：长熊段纵轴会逐档下降，刻度数字会变。这是把波动放大的
必要成本。

**配套校验**：轴顶值由 `axis.ts` 预计算成每帧表，校验脚本必须**直接读那张表**，
不得自行复刻算法——否则校验器和实现各算一套，漂移了照样报"通过"。

#### 2.4.7 音频规范（新增）

| 维度 | 标准 |
|---|---|
| BGM 风格 | 与内容情绪匹配（紧张/舒缓/史诗） |

#### 2.4.8 字幕规范（新增）

> **v4.0 修订**：原「位置 y=1700-1800」与 2.4.9 冲突。y>1440 已被平台底部文案区
> 占用、y>1700 被交互条占用，字幕放在那里等于投给平台 UI 看。下移到安全区内。

| 维度 | 标准 |
|---|---|
| 位置 | **y=1340–1420**（2.4.9 安全区内，图表时间轴之上） |
| 字号 | 32-36px |
| 颜色 | 白色 `#FFFFFF`，带黑色描边 |
| 动画 | 淡入淡出，与叙事同步 |
| 对齐 | 居中对齐，横跨 x=80–880 |

若字幕与图表时间轴争位，按优先级取舍：**图表刻度 > 字幕**。宁可去掉字幕，
也不得把刻度或金额标注推到 x>880 或 y>1440。

#### 2.4.9 UI 安全区规范（新增，强制）

短视频不是全屏可见。抖音竖屏会叠加平台 UI，关键信息压在安全区外会被遮挡或与按钮重叠。
**所有承载信息的元素必须落在安全区内，只有装饰性元素（背景渐变、满宽色条、网格线）可以出界。**

**1080×1920 下的 UI 占位**

| 区域 | 范围 | 平台元素 |
|---|---|---|
| 右侧交互栏 | x > 880 | 头像、点赞、评论、收藏、分享竖排按钮 |
| 底部文案区 | y > 1440 | 昵称、标题文案、音乐信息 |
| 底部交互条 | y > 1700 | 头像行、进度条 |
| 顶部状态区 | y < 130 | 顶部导航与状态提示 |

**内容安全区（硬约束）**

| 方向 | 边界 | 说明 |
|---|---|---|
| 左 | x ≥ 80 | |
| 右 | x ≤ 880 | 右侧 200px 全部留给交互栏 |
| 上 | y ≥ 130 | |
| 下 | y ≤ 1440 | 核心信息（标题、数据卡、图表、刻度、事件卡标题）一律不得越过 |

**次级内容带（可放可不放内容，不放关键信息）**

| 范围 | 用途 |
|---|---|
| y = 1440–1700 | 阶段注解、辅助说明，可被文案区轻微遮挡。**不得放金额、日期、事件标题** |
| y = 1700–1920 | 仅合规条（会被交互条压住一角，属可接受设计） |

**当前金额标注（v4.0 新增，强制）**

观众的核心疑问是「此刻我账户里是多少钱」。这条信息必须**跟着笔尖走**，
不能只放在固定角落：

| 要求 | 说明 |
|---|---|
| 形态 | 圆角标签贴住播放头端点，深底 `#2A1220` + 粉边，含「此时持有」+ 金额 + 单位 |
| 越界处理 | 距右缘不足时**自动翻转**到播放头左侧，不得压进 x>880 |
| 纵向回推 | 贴近绘图区上下边界时纵向夹取，保证整体在绘图区内 |
| **绘制层级** | **必须画在回撤底纹、网格、曲线之后** |

> 最后一条是踩过的坑：标签若先于不透明底纹绘制，播放头一进入回撤段
> （例如 2020-08~2023-03 的长期回撤）金额就整块被覆盖，恰好在最需要
> 提示「还剩多少钱」的段落消失。层级顺序属于功能正确性，不可提前。

**例外白名单**（允许出界，不算违规）

- 顶部 10px 品牌色条、底部合规条底色：满宽通栏
- 背景径向柔光、装饰性网格线
- 曲线本身可延伸到 x=880 边界，但**刻度文字、月份标签、数据标注文字**必须收在 x ≤ 880 内

**渲染后校验（不可跳过）**

抽样 ≥ 12 帧（建议覆盖每个事件节点 ±12 帧，v4.0 第 004 期实测采 47 帧），
用像素阈值提取内容包围盒，逐帧断言：

```
min_x ≥ 80   max_x ≤ 880   min_y ≥ 130   max_y ≤ 1440   （排除色条与合规条后）
```

任一帧越界即判定不合格，必须调整版式后重渲。

**校验器的两个必备设计（v4.0 补充）**

1. **按行排除豁免带**，不要整帧一刀切。顶部品牌条 y∈[0,12] 与底部合规条
   y∈[1850,1920] 是通栏设计，若不做行级排除，校验器会永远报越界而失去意义。
2. **装饰色也要排除**：背景 `#090409`、柔光、网格 `#22161E`、回撤底纹 `#3E1620`
   都会把包围盒撑到 x=0 或满屏。需用色板距离过滤，否则误判。

**已知易踩的坑**

| 坑 | 现象 | 正解 |
|---|---|---|
| Y 轴刻度文字 | `textAnchor=end` 锚在 `PX0-16`，「8,000」宽约 62px，实际铺到 `PX0-78` | 给绘图区左侧留 88px 装订沟，`PX0 = SAFE_X0 + 88` |
| 标签层级 | 浮动金额被回撤底纹覆盖 | 标签必须后画 |
| 纵向预算 | 逐块加高后总和悄悄越过 1440 | 版式表写出各块起止并做相加校验 |

#### 2.4.10 呈现层规范（v5.0 新增，强制）

> 四项改进一次落地：**分段配速、实时累计、版面重分配、关键节点标注**。
> 所有常量与公式的唯一来源是 `src/reveal.ts` 和 `src/layout.ts`；
> 校验器（check_readout / list_frames / diag_v5）必须 `import` 实现产物，
> **禁止复刻公式**——两套实现漂移了照样报"通过"。

##### 2.4.10.1 分段配速（`src/reveal.ts`）

全片 2760 帧里，绘图区曲线的推进不再匀速，而是"事件段多占帧、平庸段少占帧"：

| 规则 | 值 | 理由 |
|---|---|---|
| 配速窗 | `REVEAL_START=150` → `REVEAL_END=2640`（首尾各留 90 帧给钩子/收尾） | 曲线从不与钩子、收尾条抢画面 |
| 锚点集 | 事件月 idx ∪ {0, N} | 事件卡与曲线到达必须同帧（`evFrame` 是同一张表） |
| 段长 | `max(90, K·span)`，K 由二分求解使总和 = 2490 | 跨度大的段（如 42 个月长熊）自动吃掉更多时间 |
| 残差 | 二分后差额摊到最长段 | 总帧数精确闭合，末月恰落 2640 |
| 最短停留 | `MIN_DWELL = 90` 帧（3 秒） | 任何事件都读得完；对应 2.4.3"节点停留" |
| 连续性 | `revealAt(frame)` 连续值 + `kfAt` = `revealAt×80`，读数/相机/游标全部由它驱动 | 一处改速，全片同步 |

第 006 期实测（`node list_frames.mjs`）：15 个事件帧号全按分段配速落位，
最小相邻间隔 90 帧；`valueAt` 与 `NAV` 逐点核对全 ok。
**改配速只允许改 reveal.ts**，改完必须重跑 list_frames 复核间隔与数值。

##### 2.4.10.2 数据卡实时累计（`src/Video.tsx`）

卡片显示的累计收益率由 `totalPctAt(frame)` 按**当前配速时刻**计算，
`frame < REVEAL_START` 显示起点 0%，与曲线、读数严格同源：

- 严禁把 `METRICS.totalRet`（终值 2161.50%）直接钉在卡片上——第 3 秒就剧透结局，
  后面 80 秒无人再看。
- 峰值时刻卡片自然显示当帧累计（第 006 期 idx77 ≈ +3453%），收尾 150 帧才归位终值。
- 负值走 `C.down` 色（`totalPct < 0`）。

##### 2.4.10.3 版面重分配（`src/layout.ts`）

三行标题 + 大数据卡挤占绘图区的旧版式（标题 y178–444、绘图区仅 300px 高）
废弃。新预算（详见 2.4.6 版式表）：

```
期号 130..176 → 标题 178..356（两行×74px） → 细条卡 368..464（96px）
→ 读数 508·572 → 绘图区 612..1112（500px，+66% 行情空间）
→ 轴 1146 → 阶段条 1216..1237 → 事件卡 1248..1438
```

- `layout.ts` 是**版面常量唯一来源**：`PY0/MAIN_BOT/PX0/PX1/FLOAT_W/CORNER/TOTAL_FRAMES` …
  NavChart、Video、axis、check_safe、diag_v5 全部同源 import。
- **同源原则**：发现版式问题改 `layout.ts` 一个值，所有消费方与校验器同步生效。

##### 2.4.10.4 关键节点标注（BeatOverlay，`src/NavChart.tsx`）

配置在 `episodes.py` 每期的 `beats` 字段，经 `gen_data_ts.py` 发射为
`BEATS = [{idx, tag}]`（默认 ≤4 个，支持显式字段覆盖自动兜底）：

| 项 | 规则 |
|---|---|
| 选点 | 区间最高、最深回撤、跌破本金、里程碑突破（翻倍/整数关口）各取 1，互不重复 |
| 线 | 虚线 + 金标签 `C.gold`，x 从 `PX0` 到 `PX1` 满绘图区宽（**不进装订沟**，避免撞 Y 轴刻度） |
| 标签翻侧 | 左侧空间 < 标签宽 1.6 倍时右对齐；上下夹紧在绘图区内 |
| 随配速 | 只在 `kfAt(frame) ≥ beat.idx` 后出现；旧 beat 以 0.5 kf 交叉淡出，最新 beat 常驻 |
| 量程联动 | `v > top` 时跳过绘制（曲线本身也在顶上，线标没有意义） |
| 层序 | DD 底纹 → 网格/刻度 → 峰值线 → 阶段线 → 曲线 → 事件点 → **beat 虚线+金标签** → 扫描游标 → 浮标 |

## 七、文件命名规范

**视频文件名（v5.1 起）**：股票名称 + 创作日期，不再拼接期号/拼音/代码/区间/钩子类型：
```
{股票名称}_{创作日期YYYYMMDD}.mp4

示例：
中际旭创_20261006.mp4
北方华创_20261004.mp4
```

**封面与主片同基名**：
```
{股票名称}_{创作日期}_coverA.png
{股票名称}_{创作日期}_coverB.png
```

> 股票名称用行情软件里的中文简称（如「中际旭创」），不用拼音/英文名。
> 期号、代码、数据区间不进文件名——期号见画面左上期号条与选题卡，
> 区间与指标见数据复核稿；文件名只回答"哪只票、哪天做的"。
> 存量文件（ep001–ep006）不追溯改名，新规则自下一期起执行。

**项目目录结构**：
```
单标的系列/
├── 01_选题库/
│   ├── 选题总表.xlsx
│   └── {期号}_选题卡.md
├── 02_数据/{期号}_{代码}/
│   ├── k_{代码}.txt
│   ├── data.json
│   └── metrics.json
├── 03_文案/{期号}_{代码}/
│   ├── title.txt
│   ├── script_data.py
│   └── subtitle.srt
├── 04_渲染/{期号}/
├── 05_成片/{期号}_{代码}.mp4
└── 06_归档/{期号}_归档清单.md
```
